# Видео для лендинга

## Структура

```
videos/
├── phone/        ← видео для мокапа телефона (вертикальное)
│   ├── hero-intro.mp4          ← главная секция Hero
│   └── hero-intro-poster.jpg   ← постер-кадр (первый кадр)
│
└── README.md
```

Каждому видео — свой постер: без него мокап до загрузки показывает пустоту.

## Требования к видео

- **Разрешение:** нативное разрешение записи, вниз не масштабируем. Мокап
  телефона — 320 px по CSS, но на retina это 640–960 физических пикселей.
- **Формат:** MP4, H.264 **profile high** (не baseline — см. ниже).
- **Длительность:** 10–30 секунд, зацикленное.
- **Без звука** — autoplay требует `muted`, дорожку вырезаем совсем (`-an`),
  иначе она едет мёртвым грузом.
- **Вес:** ориентир до ~3 МБ. Файл грузится у каждого посетителя лендинга.

WebM (VP9) не делаем: на коротких тёмных UI-скринкастах он проигрывает H.264
по весу при сопоставимом качестве, а второй файл — лишний артефакт на
поддержку. Проверено на `hero-intro`: VP9 CRF 34 — 2.97 МБ против 2.81 МБ
у H.264 CRF 28.

## Конвертация через ffmpeg

```bash
# MP4 (H.264 high, без звука, оптимизированный для web)
ffmpeg -i input.mov -c:v libx264 -profile:v high -crf 28 -preset slow -an \
  -movflags +faststart output.mp4

# Постер (первый кадр)
ffmpeg -i output.mp4 -vframes 1 -q:v 3 output-poster.jpg
```

`-profile:v high` обязателен. Экраны записи часто выходят в
`Constrained Baseline` — профиле без B-кадров и CABAC, — и такой файл весит
кратно больше при той же картинке. Онлайн-конвертеры профиль не меняют, поэтому
дают экономию в единицы процентов; `hero-intro` на этой команде сжался с 8.89 МБ
до 2.81 МБ (−68%) без потери разрешения.

CRF 28 — точка перегиба: визуально неотличимо от исходника, а CRF 30 экономит
ещё полмегабайта уже ценой заметных артефактов на градиентах тёмного UI.
